## Key Challenge

Implement, validate, and demonstrate a focused AI-enabled software prototype that addresses a real stakeholder need. Show that the implemented behavior, architecture, controls, and evidence remain aligned with the problem and requirements.

## Instructions

The Final Project continues the work developed through Assignment 1 and Assignment 2. You may continue the same project and use its Problem Briefing, requirements, architecture, and solution design as the foundation for the prototype. If you select a different project, establish an equivalent problem definition, requirements baseline, architecture, and solution design before implementation.

Implement a bounded prototype that demonstrates the proposed capability. Use AI assistance as part of a disciplined development process. You remain responsible for the code, design decisions, validation, source traceability, security and privacy controls, and observed behavior.

- **Publish the project in a GitHub repository.**
- The repository must include a clear `README.md` that explains how to understand, set up, run, test, and evaluate the prototype.
- Do not publish confidential, personal, or unauthorized data, credentials, or keys.

**Advisory:** Treat the Final Project as a portfolio artifact. Build a focused solution that you can demonstrate, explain to a stakeholder, and maintain after the course. A small capability with clear evidence and dependable behavior is stronger than an unfinished broad platform.

## How to Think About It

- Start with the problem, stakeholder need, requirements, architecture, and design decisions. Keep a visible link between each important implementation choice and the reason for it.
- Define the smallest prototype slice that demonstrates a meaningful end-to-end workflow, including inputs, AI-assisted processing where appropriate, controls, review or escalation, and outputs.
- Build in short iterations. Use AI to propose code, tests, explanations, and alternatives. Review every candidate, run the system, and correct defects.
- Validate functional behavior, failure and exception conditions, quality attributes, source traceability, and retained human authority.
- Keep the repository and README current. Another developer should be able to understand the problem, set up the prototype, run it, and identify its limits.
- Document what the prototype demonstrates, what remains out of scope, and what evidence supports the claims you make about it.

## Using GenAI

- Use GenAI to plan implementation slices, explore alternatives, generate or revise code, propose tests, diagnose defects, refactor, and improve technical documentation.
- Treat generated code, tests, explanations, and recommendations as candidates. Review them for correctness, security, privacy, maintainability, and fit with the requirements and architecture before use.
- Record material AI assistance, validation work, rejected or revised outputs, and known limitations in the project documentation or repository history.
- Use retrieval, agentic workflows, or model adaptation only when they fit the problem and the student can validate the resulting behavior.
- Maintain human authority over consequential decisions, approvals, published outputs, and changes to the repository.

## What You Have to Do

You are the developer. GenAI can assist with implementation, but you remain responsible for the prototype, its evidence, and the submitted work.

- Select a project scenario. You may continue the project from Assignments 1 and 2 or define an equivalent baseline for a different scenario.
- Refine the problem briefing, requirements, architecture, and solution design when implementation evidence identifies a needed change. Record the rationale and effect of the change.
- Implement a bounded, end-to-end prototype. Include the interfaces, data and interaction flows, controls, review points, and outputs needed for the selected capability.
- Validate the prototype with representative inputs, expected results, exceptions, failure cases, and relevant quality attributes. Record the evidence and remaining limitations.
- Maintain the source code in a GitHub repository. Use meaningful commits and include a README with the project purpose, architecture summary, prerequisites, setup steps, run instructions, test instructions, sample or authorized data guidance, known limitations, and repository link.
- Prepare a runnable demonstration. Deploy the prototype when appropriate, or provide reliable local run instructions and a demonstration path.
- Update the Solution Design Report so it distinguishes the planned solution from the implemented prototype and traces the problem, requirements, architecture, implementation, validation evidence, and observed behavior.
- Prepare the final presentation and portfolio evidence. Explain the problem, stakeholder value, implementation, architecture, AI assistance, validation, limitations, and next steps.

## Deliverables

Submit the following individual-project deliverables.

### 1. Solution Design Report

- Update the Assignment 1 and Assignment 2 work to reflect the implemented prototype.
- Include the problem scenario, stakeholders, requirements, architecture, solution design, implementation summary, validation evidence, observed behavior, limitations, and traceability across the project.
- Link to the GitHub repository and runnable demonstration or documented local run path.

### 2. Source-Code Repository

- Provide the GitHub repository link (add to your PDF report).
- Structure the project to match current standards for top-notch GitHub repo projects, including the README.md, LICENSE, contribution, others.
- Include a strong README that states the project purpose, solution architecture, setup, configuration, run and test instructions, and others.
- Include the implementation, supporting configuration, tests, and relevant project documentation.
- Include the process to stand up and execute the project from the GitHub repository.

### 3. Running Prototype

- Demonstrate the bounded end-to-end capability; describe in your PDF report using your own words.
- Provide access through a deployment, recorded demonstration, or reliable local run instructions, as appropriate for the project.
- Show how the prototype handles representative normal and exception paths.

### 4. Final Presentation and Portfolio Evidence

- Present the problem, stakeholder value, implemented solution, architecture, validation results, AI assistance, limitations, and next steps.
- Include links or evidence that allow a reviewer to inspect the report, repository, prototype, and demonstration.
