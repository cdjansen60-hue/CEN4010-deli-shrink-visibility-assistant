## 1. Problem Reality (20 points)

**Expectation:** The project addresses a real, specific problem in a recurring workflow. It identifies stakeholders, current conditions, impact, and credible evidence that the problem matters.

**Good idea:** The project presents a clear technical demand aligned with a well-described business or social workflow. There is an explicit and coherent definition of 'who cares' and you executed a discovery session with a real user.

**Grading scales:**

- **Borderline (10 pts):** The project addresses a plausible problem for a defined user group, but evidence of demand, stakeholder engagement, or impact remains limited.
- **Weak (5 pts):** The project has a broad or weakly supported use case. The stakeholder, workflow, or impact is unclear.
- **Misaligned (0 pts):** The project is a solution looking for a problem. It identifies no credible stakeholder, workflow, impact, or reason the project matters beyond personal convenience.

## 2. Originality (20 points)

**Expectation:** The proposed solution is new and interesting for its context, with a distinct and justified approach to the identified problem.

**Good idea:** The project moves beyond a generic app, website, or chatbot and proposes a solution approach that is simple to understand, consumable, and innovative. The solution is designed to accommodate the stakeholder and workflow.

**Grading scales:**

- **Borderline (10 pts):** The project adapts a known solution to a defined context and includes some thoughtful improvement or differentiation.
- **Weak (5 pts):** The project is based on a common idea with limited adaptation, originality, or explanation of why it is the right approach.
- **Misaligned (0 pts):** The project presents a generic app, website, chatbot, or copied template without a clear reason why it fits the problem or offers a distinct solution.

## 3. Documentation Quality (30 points)

**Expectation:** The project record is complete, professional, consistently formatted, well illustrated, human-readable, and easy to consume.

**Good idea:** The report, diagrams, repository, links, and presentation form one coordinated project record. Each artifact helps a reviewer understand the problem, proposed solution, technical decisions, and evidence.

**Grading scales:**

- **Borderline (20 pts):** Documentation is mostly complete and readable, but some sections, diagrams, labels, explanations, links, or formatting need improvement.
- **Weak (20 pts):** Required materials are present but difficult to use because of poor organization, inconsistent formatting, missing labels, disconnected diagrams, or incomplete explanations.
- **Misaligned (0 pts):** The project relies on uncoordinated GenAI copy-and-paste text, LLM-generated content without student review, or material that is disconnected, poorly labeled, or difficult to read.

## 4. Technical Quality (30 points)

**Expectation:** Technical work is coherent, aligned with the problem, and makes use of the techniques and guidance provided during class.

**Good idea:** The project implements a focused end-to-end capability using relevant software-development techniques. It demonstrates what works, how the work was validated, and which limitations remain.

**Grading scales:**

- **Borderline (20 pts):** The technical work supports the main project goal, but the design rationale, implementation completeness, use of course techniques, testing, or validation evidence needs refinement.
- **Weak (10 pts):** The technical work is partially complete, weakly connected to the problem, or supported by limited validation evidence.
- **Misaligned (0 pts):** The technical explanation or implementation is excessive, uncoordinated GenAI copy-and-paste content, disconnected from the project description, or does not demonstrate meaningful use of the course techniques.
